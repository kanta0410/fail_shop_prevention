# 名古屋EDA: 次回以降のネクストステップ (Next Steps)

これまでの「データ浄化」「リーク・ノイズの徹底排除」により、真の意味で立地と業態に基づいたクリーンな廃業予測モデルのベースライン（Test PR-AUC: 0.9153）が完成しました。
この強固な土台の上で、次回以降は以下のステップを進めていくことを提案します。

## 1. 他都市データへの汎化性能の検証（クロスエリア・バリデーション）
現在、モデルは名古屋のデータに最適化されていますが、ビジネスとして展開するためには「東京」や「大阪」でも通用する普遍的な法則（例：競合との距離、中心地との距離など）である必要があります。
- **Action:** 既に取得済みの「東京23区」「大阪市」のデータを今回と同じパイプラインで処理し、名古屋で学習したモデルが他都市の廃業も正確に予測できるかを検証する。

## 2. 新たなドメイン特徴量の開発（テナント履歴・相性）
フロア特徴量はノイズが多いため一旦削除しましたが、空間データをさらに活用する余地はあります。
- **テナントジンクス（負の履歴）:** 過去に同じ座標（ビル）で複数回廃業が起きている「鬼門」の立地であるかをフラグ化する。
- **業態同士の相性:** 「最寄り飲食店との距離」が最も重要でしたが、それをさらに掘り下げ、「自分の業態（カフェ）の近くに、特定の業態（大学、あるいは他のカフェ）があるか」といった相乗効果・食い合い効果を特徴量化する。

## 3. モデルのハイパーパラメータ・チューニング
現在は XGBoost や LightGBM のデフォルトパラメータに近い状態で評価しています。
- **Action:** Optuna 等を用いて、浄化されたデータセットに対する最適なパラメータを探索し、さらなる精度向上（過学習の防止と予測確率のキャリブレーション）を図る。

## 4. 予測結果の地図上での可視化（ヒートマップ作成）
精度の高い予測確率が出せるようになったため、これを名古屋市の地図にマッピングします。
- **Action:** 「どこにカフェを出せば生存率が最も高いか」が一目でわかるヒートマップやシミュレーション結果を可視化し、アプリ化（OwnerBrainダッシュボード）に向けたプレゼン資料を作成する。

---
**総括:**
今回の反省と浄化プロセスにより、不当なショートカット（リーク）で精度を稼ぐモデルから脱却できました。次回は、この「正しいモデル」を使って、ビジネス価値に直結する分析（他都市展開、地図可視化、業態ごとの最適立地探索）にシフトしていくフェーズとなります。
